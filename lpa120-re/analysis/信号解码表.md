## 更正 · 纵向(ACC)与横向(LCC)必须分开统计（2026-11-02）

**此前表述**："LCC 激活占比 23%" —— 只统计了横向，漏掉纵向，容易被误解为"巡航"。

**实车验证的功能层级**（用户确认 + 数据证实）：

```
ACC 是基础功能；LCC 是 ACC 之上的子功能（有车道线才叠加）
→ 只有两种组合：仅 ACC、ACC+LCC
→ "仅 LCC" 结构上不可能
→ 车道线丢失时 LCC 退出，ACC 保持
```

### 数据验证（`cap_c3286193`，16,522 帧 0x18D）

```
横向 lat=1        : 4,078 帧 (24.7%)
纵向 acc=1        : 7,064 帧 (42.8%)
lat=1 且 acc=0    : 0 帧        ← 不变式成立
LCC 退出事件 4 次，ACC 全部保持   ← 与描述一致
```

### 正确判据

| 维度 | 信号 | 判定 |
|---|---|---|
| 纵向 ACC | `0x0B7 byte3` bit6=ACCStates / bit4=ACCRequest | `0x40` 已介入、`0x10` 请求中 |
| 横向 LCC | `0x18D byte8` bit3 | 仅在 ACC 已激活时可能为 1 |
| LKA 命令枚举 | `0x083 byte12[2:0]` | `LKA.FuncMode = byte12 & 0x07`，实测值 `{1,2,3,5}`；完整字节中的 `0x0B/0x4B` 含其它位，禁止再按 `0xB` 判断 |
| 命令回显 | `0x142 byte5[2:0]` | 原样回显 `LKA.FuncMode`，不是独立状态证据；实际横向执行只认 `0x18D byte8.bit3` |

### 对 openpilot 的影响

```
cruiseState.enabled 必须看 ACC（纵向）
只读 latActive 会把 "ACC 开着但车道居中未激活" 的 31 秒误判为未开辅助
```

解码器 `decode_capture.js` 已补 `accActive` / `accRequest` 两列，并内置不变式检查（输出 0 为正常）。

## 5. 取值与时间基准注意事项（2026-11-03 追加）

以下三条来自 `handoff_2026-11-01\08_timebase_data_quality.md`，**解码公式本身不变**，变的是"取哪一帧、怎么算时间"。

### 5.1 车速：优先 0x184，不要只取 0x182

| 帧 | 在线窗口（100 ms 粒度） | 结论 |
|---|---|---|
| 0x184 四轮速 | **100%**，稳定 50 Hz | ✅ **vEgo 主源**（四轮平均） |
| 0x182 整车车速 | **29.7%**（静默 1.1–1.7 s 成段，同期 0x18D/0x184 满勤） | 🟡 仅作对照 |

两者中位差 **−0.16 km/h**（p95 ≤ 0.08），所以"公式对不对"没问题，问题是 0x182 **经常不在总线上**，
拿它做插值/差分就会得到陈旧样本。

N5 已排除“速度变化触发”：30 文件逐文件 AUC 中位数 0.500；counter 跨静默仍按 20 ms 推进
15,705/15,705，簇首间隔 p50=1.301 s。0x182 应视为“20 ms 内部时基 + 约 1.3–1.4 s
外层突发窗”，精确门控源需发送节点/网关配置（见 `0x182发送门控_2026-11-03.md`）。

### 5.2 任何 dt 类量必须 ≥100 ms 窗口

时间基只有 **1 ms**（1200 fps → 每毫秒 2 帧 → 约一半帧时间戳相同）。
相邻帧差分在数学上无意义；减速度/周期/加速度一律用 ≥100 ms（推荐 200 ms）窗口，且剔除窗口内 >60 ms 空档。

### 5.3 0x184 byte10 是四个打包的 2-bit 车轮方向字段（2026-11-03 更正）

先前把整个 byte10 当作一个枚举，因而误写成“只有 0x55/0x00、不能判断方向”。DWARF 布局与全库原始数据均否定该说法：

| 位 | 字段 | 运行时取值 |
|---|---|---|
| b10[1:0] | FL direction | 0/1/2 |
| b10[3:2] | FR direction | 0/1/2 |
| b10[5:4] | RL direction | 0/1/2 |
| b10[7:6] | RR direction | 0/1/2 |

语义为 **0=静止、1=前进、2=倒退、3=未观测/保留（解码器按 invalid 处理）**。14 会话共 62,405 帧 0x184：
方向码 2 出现于 429 帧，`03d93adb` 中 276 个 50 Hz 栅格为 `2/2/2/2`，全部同时处于 R 挡；
其中 252 行 `vEgo < -0.1 m/s`，最低 −0.783 m/s。0x55 是 `1/1/1/1`，0xAA 是 `2/2/2/2`，0x00 是 `0/0/0/0`。

接入规则：先按每轮 direction 给轮速幅值加符号，再求四轮均值。**不得直接按 gear 给 vEgo 取负**，因为换挡瞬间车辆仍可能沿原方向滑行；direction=3 时该栅格应判无效，不能静默给出 0 或正速度。

### 7.1 拨杆：功能已解，按键本体不在 CCAN

| 操作 | CAN 效果 | 证据 |
|---|---|---|
| **下拨 1 次** | **启动 ACC** | `双拨3` 六次 ACC 0→1，`SpeedCtl` 立刻出现设定值 |
| **紧接着再下拨第 2 次** | **启动 LCC**（叠加在 ACC 上） | ACC 后 0.17–0.21 s LCC=1，共 4 次（反馈边沿，非两次动作间隔；窗口上限未测）；`单拨2` 只单次下拨则 LCC 全程为 0 |
| **上拨 1 次** | **ACC + LCC 一起退出** | ACC 与 LCC 在 30 ms 内先后归零、`SpeedCtl`→0（4 次） |

全库扫描无独立按键报文；可观测的只有下游状态（`0x083 b15`、`0x18D b8/b22`、`0x143 b6`）。

### 7.2 FuncMode 四值语义（带标签）

**关键区分：退出时 ACC 是否保留**（驾驶员确认 + 数据一致）。

| fm | LCC | ACC | 触发 | 证据 |
|---:|---|---|---|---|
| 1 | 退 | **退**（或延迟 0.3–0.5 s） | 刹车为主（3 例中 2 例 `brake=1`） | 接管1 27.63 s、接管2 18.55 s；另有 `双拨` 42.56 s（`brake=0`，疑为上拨） |
| 2 | 退 | **退** | 上拨（全退） | `双拨3` 四个下降沿、接管2 44.27 s、shuangbo2 30.25 s（5 例） |
| 3 | **在控** | 开 | — | 所有上升沿 |
| 5 | 退 | **保留** | 抢方向（扭矩）/ **打转向灯** / 线丢失 | 接管2 35.54 s（+5.02 Nm）、shuangbo2 27.53 s（−4.37 Nm）、**去 46.77 s（打左灯，20 ms 后 lat 掉，ACC 全程保留，fm=5 持续 3.0 s）**、接管1 14.32 s（无输入） |

→ `去` 中 3 s 的 fm=5 归入**LCC 单退（ACC 保留）**。

> **可靠的只有一条**：`fm=5 ⇔ ACC 保留`（3/3）；`fm=1` 与 `fm=2` 都是 ACC 也退，**两者之间不能严格区分**（`fm=1` 里混了一例 `brake=0`）。

**判据写法**：

```
LCC 单退（可继续跟车）= lat 1→0 且 ACC 仍为 1  → fm=5
全退（需重新启动）    = lat 1→0 且 ACC 也变 0  → fm=1（刹车）/ fm=2（上拨）
```

### 7.3 设定速度（`ACC.SpeedCtl`）—— 单位 = ×0.1，仪表读数上偏 ≈4.6%

**两条独立判据**：

**① 滚轮步长（最硬）**：驾驶员用滚轮从 50 逐格上调，每档 +1 km/h。设定值原始计数的步长直方图：

```
10 计数 ×14 次  ← 众数
20 / 30 计数     连拨两/三格
9 / 8            量化抖动
=> 1 km/h = 10 计数 => 单位 0.1 km/h/计数
```

**② 默认值规则**（驾驶员确认「低于 50 → 默认 50；高于 50 → 取当前车速」）：

| 场景 | 车速 | 设定 raw | ×0.1 | ×0.1046 |
|---|---:|---:|---:|---:|
| 低于 50 启动（6 次） | 35.9–47.4 | **恒 477** | 47.7 | 49.9 |
| **高于 50 启动** | **51.3** | **507** | **50.7** ✓ | 53.0 ✗ |

「高于 50 取当前车速」只在 ×0.1 下成立（×0.1046 会算出比车还快的设定值）。

**仪表读数与 CAN 的比值**：47.7→50、57.4→60、76.5→80、95.9→100，即 **1.043–1.048（≈+4.6%）**。
这是车速表法规允许的上偏，**不是 10 km/h 圆整**（逐格 +1 时圆整会让数字卡住不跳）。

→ **`SpeedCtl = raw × 0.1`**（是否等于 `vCruise` 待确认，见 `handoff_2026-11-01\09` U12）；曾按显示值反推的 ×0.1046 **作废**。

> **不要做 +4.6% 校正**（2026-11-03 定）：openpilot 全程使用 CAN 单位（`vEgo` 取 0x184、`vCruise` 拟取 0x083 设定速度，语义待确认），
> 同一套单位在控制回路内自洽；只有与 GPS/地图限速直接对比时才出现该差异，而该对比不参与控制。

### 7.4 急刹与减速度算法

`急刹1/2`：rod 最大 98 / 100（**100 饱和确认**），压力 850 / 801，减速度 ≈10.5 m/s²。
⚠ 用四轮**均值**+200 ms 窗口会得到 13–15 m/s² 的假值（ABS 单轮 40 ms 内可跳 13 km/h）；
必须用**四轮中位**+≥500 ms 窗口。
