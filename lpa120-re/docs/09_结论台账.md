### 1.2 记录格式（每行一帧）

```json
{"protocol_version":1,"device_id":"PCAN","session_id":"...","sequence":1,"channel":0,
 "timestamp_monotonic_ns":1793735619859000000,"timestamp_unix_us":1793735619859000,
 "timestamp_quality":3,"can_id":397,"is_extended":false,"is_fd":true,"brs":true,"esi":false,
 "is_remote":false,"dlc":32,"payload_length":32,"data_hex":"780242737d00f843...","capture_flags":0}
```

关键字段：`sequence`（会话内单调，跨 ID 对齐只认它）、`timestamp_unix_us`、`can_id`、`payload_length`、`data_hex`。

### 1.4 三条纪律（违反任何一条结论都会错）

```
① 跨 ID 对齐用 sequence，禁止按 timestamp 等值 join（约 50% 帧共享同一毫秒）
② dt 类量窗口 ≥100 ms，减速度推荐 ≥500 ms
③ vEgo 用 0x184（50 Hz、在线 100%），不要用 0x182（条件发送）
```

| U6 | 0x143 是什么帧 | 53,108 帧、间隔严格 20 ms（p10 19.993）；**b6.0 ≡ latActive**（53,108 帧中仅 17 例例外）；b6.7（0x00/0xA0 之别）是慢变状态位（53,108 帧仅 78 次翻转）：0x00 里 D 挡 67%、moving 53%、ACC 12%；0xA0 里 D 挡 99%、moving 92%、ACC 20% —— **与「在动/D 挡」相关但不二值**，驱动量仍未定；字节 0 疑计数器/序列 | b6.7 的驱动量；发送节点无法从 CCAN 判定 |
| U7 | 0x0CD 的两态周期 | 108,842 帧实测：短态 **p50=10 ms**、长态 **p50=29 ms**，占比 51,782 / 57,030（≈48/52）；**与 LCC 状态无关**（lat0/lat1 下都是约 47/53） | 两态是否来自两个生产者/调度器：**短/长间隔的 payload（byte1–4）16 种完全相同**，不是「两种报文交替」；更像同一发送者的节拍抖动或调度切换。仍缺发送节点信息 |
| U8 | 设定速度 >100 km/h | 未测（最高 959 = 95.9） | 高速段设定 110/120 |
| U9 | 0x184 方向码 3 | 62,405 帧中 0 次 | 传感器故障或换挡瞬态样本 |
| U10 | 0x0B7 的 ACC 状态位 | ✅ **基本闭环（2026-11-04 交叉验证）**：把 b3[6:4] 当作 3-bit 字段，与 0x083 的 ACC FuncMode 逐帧对照，96,510 帧中仅 ~130 帧冲突（≥99.8% 一致）：`4⇔mode3`（35,891）、`0⇔mode2`（25,635）、`1⇔mode1`（11,985）、`6⇔mode5`（1,724）。**engaged = 值 4**，`1` 是待命/可用。旧「req=1 是请求」的说法作废 | 剩余：极端边沿（mode5 时的 6）语义；不需要新车 |
| U11 | 仪表 +4.6% 的成因 | 推断为车速表法规上偏 | GPS 对照（稳定 80 km/h 跑 20 s） |
| U13 | ✅ **已解（2026-11-05 DBC）**：0x083 b4 = `raw×0.05 − 5`（`ADDC_ACCTargetAcc`，量程 −5..7.8） | 旧反汇编写成 `5 − raw×0.05`，符号相反；按 DBC 重算后与实测加速度相关性由 **−0.84 翻正为 +0.88/+0.85**（`设定速度1`/`接管2`） | 结案 |

### 3.2 已知缺陷 / 风险

| # | 项 | 影响 | 建议 |
|---|---|---|---|
| R1 | `aEgo`（100 ms、四轮均值）在 ABS 下不可信：峰值 18–19.7 m/s²；**改四轮中位只削 1.6 m/s²，不足以修好** | `急刹1/2`：aEgo 19.73/18.18 → `aEgoRobust`（四轮中位 + 500 ms）9.69/10.37，与 D3 的 10.5 吻合；6 包复跑硬不变式 0 | 减速度一律用 `aEgoRobust`；`aEgo` 只作瞬态指示，不要拿它做 ABS 期结论 |
| R2 | `双拨3` 出现 lat=1 且 acc=0 共 3 行、mode3 且 acc=0 共 7 行 | 软不变式违反，集中于开关边沿 | 可接受，但下游要标为边沿 |
| R3 | 时间戳 28 次 −100 µs 回退（17 包：第一批 9 + 第二批 19） | 按时间戳排序会错序 28 帧 | 一律用 sequence |
| R4 | .trc 单文件上限 100,000 条（≈87 s） | 记录会被截断 | 长测试拆分或调大上限 |
| R5 | CarState 是 JSON 影子，不是 capnp | 不能直接被 openpilot import | 接真 runtime 前先做序列化往返验证 |

### 3.3 曾被推翻的结论（避免复引）

| 旧说法 | 现状 |
|---|---|
| 0x083 b15 = LKA.SteerRate（raw×4） | 错：实测只有 0x00/0x64，是状态字节 |
| 0x290 b3.0/b3.1 是转向灯状态 | 错：那是灯输出相位，状态在 b2 |
| 单拨=ACC 取消/恢复、双拨=LCC 开关 | 错：实际是分级启动（C1） |
| vCruise = raw × 0.1046 | 错：单位是 0.1；0.1046 来自把仪表读数当刻度 |
| 0x142 是独立状态机 | 错：是 0x083 命令回显（B7） |
| 0x18D byte0 是某种标准 CRC | 错：线性类已全部排除 |
| 打灯退 LCC 会连 ACC 一起退 | ❌ 打灯是**暂停**不是退出：11 次样本中 9 次 LCC 自动恢复、ACC 保持（C4/D44）；仅长暂停或未恢复时 ACC 才退 |

## 4. 坑清单（外部 AI 最容易踩的 8 个）

```
1. 按 timestamp 做跨 ID join —— 约 50% 帧同戳，必须用 sequence
2. 解析 candump 时把 ## 后两位 flags 当 payload —— 会整体错位半字节
3. 拿 0x182 当 vEgo —— 条件发送，43–82% 时间不在线上
4. 用 gear 推 vEgo 符号 —— 必须用 0x184 b10 的每轮方向位
5. 用 0x290 b3 当转向灯状态 —— b3 是 1.25 Hz 灯输出，状态在 b2
6. 四轮均值 + 短窗口算减速度 —— ABS 时会出 13–18 m/s² 假值
7. 把 .trc 的 3 位小数当 µs —— 有效量子仍 1 ms
8. 继续爆破 0x18D byte0 的 CRC —— 线性类已被数学排除
```
