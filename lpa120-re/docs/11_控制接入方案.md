# 控制接入方案（2026-11-05 设计稿，未实施）

> 本文是**设计与验证方案**，不是已执行记录。所有注入类操作都在项目红线之外，
> 正式实施前必须完成文中的静态确认与安全设计。

## 0. 前提

- 0x083 的 E2E 已解（`CRC8_H2F` + seed 表，见 `10_E2E_CRC与seed表.md`）；
- 0x083 的发送方是 **ADDC**（DBC），EPS/VCU/IBC 是接收方；
- 目前 `ADDC = EL215` 是**高置信度推断**，尚未物理确认。

## 1. 方案一：EPS 支线 MITM（只做横向）

接入点 `CH020-2`：

| 针脚 | 信号 |
|---|---|
| CH020-2-5 | CCAN-H |
| CH020-2-6 | CCAN-L |

```
原车 CCAN 线束侧 H/L
   │
网关 CAN0  ← 双向转发所有报文
   │        拦截「主总线 → EPS」的原始 0x083
   │        替换为 OpenPilot 生成的 0x083
网关 CAN1
   │
EPS CH020-2-5/6
```

**优点**

- 不依赖 ADDC 物理身份；
- EPS 只能收到网关送来的 0x083；
- 原车 ADDC 继续服务 VCU/IBC，纵向不受影响；
- 风险面最小，适合先做横向闭环；
- 0x18D 由网关反向透传回主总线。

**限制**：只能横向。VCU/IBC 仍在主 CCAN 上，继续收到 ADDC 原始 0x083。

## 2. 方案二：EL215 支线 MITM（横向 + 纵向统一替换）

接入点 `EL215-3`：

| 针脚 | 信号 |
|---|---|
| EL215-3-13 | CCAN-L |
| EL215-3-14 | CCAN-H |

```
EL215-3 模块侧 13/14
   │
网关 CAN0
   │  双向透明转发；仅过滤「EL215 → 主总线」的 0x083
   │  控制激活时替换为 OpenPilot 0x083
网关 CAN1
   │
车辆主 CCAN（EPS / IBC / FSC / ACU …）
```

只有这样才能让 EPS、VCU、IBC 同时只收到替换后的 0x083。

### 2.1 证据链（支持 ADDC = EL215）

- DBC：`BO_ 131 ADDC_83: 32 ADDC`；
- E2E 表把报文命名为 `HPCADAS_83`；
- CRC 生成/校验代码在 QNX `lpAdasInput` / `lpCanEngine`；
- `接插件针脚表`：EL215-3 同时带 CCAN(13/14)、ACAN(15/16)、PCAN(17/18)、BCAN(19/20) —— 典型的多域控制器；
- 维修手册里 CCAN 上唯一的多域/HPC 节点是 EL215。

### 2.2 三项静态确认（正式做线束前必须做）

在维修环境、车辆静止、用 EL215-3 公母直通转接板只断开 13/14 支线：

1. 主 CCAN 仍保持约 **60 Ω**；
2. EL215 支线断开后，主总线上的 **0x083 消失**；
3. EPS 的 0x18D、IBC 的 0x184/0x185 等节点帧**仍存在**。

三项同时成立 → 确认 EL215-3 是正确的 ADDC 隔离位置。
**该测试会产生通信故障码，只能原地、维修环境进行，不能行驶。**

## 3. 灯光通道（转向灯 / 大灯）

原厂已为 ADAS 预留灯光请求接口，不必改灯线：

### 3.1 `0x23C ADDC_23C`（ETH_CANFD.dbc，1832 行）

- 8 字节 / sender = **ADDC** / receiver = **HPCBCM**；
- 字段：`ADDC_TurnLeftLightReq`、`ADDC_TurnRightLightReq`、`ADDC_emergencyLightReq`、
  `ADDC_brakelightrequest`、`ADDC_headlightrequest`、`ADDC_mirrorrequest`、`ADDC_seatbeltrequest`；
- 取值：左右灯 `0=无请求 1=关闭 2=打开`；大灯 `0=关 1=近光 2=远光`。

### 3.2 `0x1F3 HPCBCM_1F3`（B_CANFD.dbc，208 行）

- 32 字节 / sender = **HPCBCM** / receiver = ZCUL/ZCUR/ZCUB/AHLL/AHLR；
- 含 `BCM_CRC_1F3` + `BCM_RollingCounter_1F3`；
- 字段：`BCM_LTurnLampCtrl`(bit64)、`BCM_RTurnLampCtrl`(bit65)、`BCM_LowBeamHeightCtrl`、
  `BCM_SmallLightsCtrl`、`BCM_LDayLightsCtrl`、`BCM_ADBReq` 等。

### 3.3 B-CAN 物理接入

| 位置 | 针脚 | 信号 |
|---|---:|---|
| EL215-3 | 20 | BCAN-H |
| EL215-3 | 19 | BCAN-L |

（针脚依据：`接插件针脚表_2026-10-28.md` 第 19–20 行。）

### 3.4 关键判定（2026-11-05 核对全部 11 份 DBC 后）

| 报文 | 出现在哪 | 判定 |
|---|---|---|
| `0x23C ADDC_23C` | **只在 `ETH_CAN.dbc` / `ETH_CANFD.dbc`**，`B_CANFD.dbc` 里没有 | **是以太网侧映射，不是物理 CAN 帧**；在 B-CAN 上发它大概率无人接收 |
| `0x1F3 HPCBCM_1F3` | 只在 `B_CANFD.dbc` | B-CAN 上的真实帧，BCM 发出、区域控制器/AHLL 接收；**E2E 表已知**（`2c 98 13 db …`） |

**因此灯光控制的可行路径要改：**

1. ~~在 B-CAN 上发 0x23C~~ → 不成立（它不是 CAN 帧）；
2. 走原厂请求接口 → 需要 **以太网**（SOME/IP/DDS）接入，门槛高；
3. **模拟 `0x1F3`**（B-CAN，发往区域控制器/ZCUL/ZCUR/ZCUB）→ 技术上最直接，但要与 BCM 自己的 20 ms 发送仲裁；
4. 模拟组合开关请求（COM-CAN）→ 另一条思路，未验证。

`0x23C` 的 13 个信号里还有 `SWB_*`（方向盘滚轮/按键）与 `TCM_GearLevelSwitchSts`、`FSC_IHBC_Mode`——进一步说明它是“ADDC 汇总的多源请求包”，经以太网发给 BCM，而不是 CAN 帧。

### 3.5 `0x1F3` 关键灯光位（76 个信号中的控制/状态位）

| 位 | 信号 | 宽度 | 含义 | 接收方 |
|---:|---|---:|---|---|
| 0 | `BCM_CRC_1F3` | 8 | CRC（E2E 表已知） | ZCUL/ZCUR/ZCUB/AHLL/AHLR |
| 8 | `BCM_RollingCounter_1F3` | 4 | 计数器（模 16） | AHLL/AHLR |
| 16 | `BCM_ADBReq` | 1 | 自动远光请求 | AHLL/AHLR |
| 17 | `BCM_ADBActivationSts` | 1 | 自动远光激活状态 | AHLL/AHLR |
| **64** | **`BCM_LTurnLampCtrl`** | 1 | **左转向灯输出** | ZCUL/ZCUR/ZCUB |
| **65** | **`BCM_RTurnLampCtrl`** | 1 | **右转向灯输出** | ZCUL/ZCUR/ZCUB |
| 66 | `BCM_LowBeamHeightCtrl` | 3 | 近光高度 | AHLL/AHLR |
| 69 | `BCM_SmallLightsCtrl` | 1 | 示廓灯 | IVI/ICU |
| 70/71 | `BCM_LDayLightsCtrl` / `R` | 1 | 日行灯 | IVI/ICU |
| **72** | **`BCM_LowBeamCtrl`** | 1 | **近光** | AHLL/AHLR |
| **73** | **`BCM_HighBeamCtrl`** | 1 | **远光** | AHLL/AHLR |
| 76 | `BCM_ADSLightCtl` | 1 | ADAS 灯光控制 | ZCUL/ZCUR/ZCUB |
| 88 | `BCM_Brake_LampCtrl` | 1 | 刹车灯 | ZCUB |
| 89 | `BCM_BackUp_LampCtrl` | 1 | 倒车灯 | ZCUB |
| 90 | `BCM_RearFogCtrl` | 1 | 后雾灯 | ZCUB |
| **92** | **`BCM_HazardLightCtrl`** | 1 | **双闪输出** | ZCUL |
| **144** | **`BCM_ADASHeadLampReq`** | 2 | **ADAS 大灯请求（0/1/2）** | CLOUD |
| **152** | **`BCM_ADASTurnLampReq`** | 2 | **ADAS 转向灯请求（0/1/2）** | CLOUD |
| 154 | `BCM_StopLampReqSrc` | 3 | 刹车灯请求来源 | CLOUD |
| 165 | `BCM_AutoHighBeamSts` | 3 | 自动远光状态 | IVI/ICU |

两个关键观察：

1. **`0x1F3` 同时带控制位（`*Ctrl`）和 ADAS 请求状态（`ADAS*Req`）**——后者说明 BCM 会把 ADAS 的请求回显出来，可用作“请求是否被接收”的反馈；
2. 真正驱动灯的执行件是 **ZCUL/ZCUR/ZCUB/AHLL/AHLR**，它们都是 `0x1F3` 的接收方 ⇒ 在 B-CAN 上伪造 `0x1F3` 是可直接点灯的路径（但要与 BCM 的 20 ms 发送仲裁）。

## 4. 验证顺序（灯光）

1. 在 EL215-3 的 20/19 高阻并联，**只做被动抓包**；
2. 分别操作左转、右转、双闪、近光、远光；
3. 确认实车上是否存在 `0x23C`、`0x1F3`，以及它们实际在哪条总线上；
4. 验证 counter、E2E、发送者与灯光反馈；
5. 再决定用原厂 `0x23C` 请求接口，还是模拟组合开关请求。

**在这一步完成前，不应发送任何灯光控制帧。**

## 5. 硬件要求

不要用单个普通 panda 直接串联。永久安装至少需要：

- 两路**真正独立**的 CAN-FD 控制器；
- ISO CAN-FD，500k/2M，BRS；
- 网关本机实时双向转发（不能依赖 Linux 用户态）；
- **硬件旁路继电器**：设备掉电时恢复原车 13↔13、14↔14；
- 独立看门狗；默认状态必须是原车直通；
- 网关异常时**不得保持**最后一次转向/加速度请求；
- OpenPilot 电脑只给网关“目标命令”。

> 注意：comma panda（MCP2515）是**经典 CAN**，读不了 32 字节 FD 帧；它只能做低带宽旁路验证，不能承担 FD MITM。

## 6. 终端电阻

切开前先断电测量：

- 主车线束侧 H-L 预计约 **60 Ω**；
- EL215 模块侧单独测量，确认模块是否内置 120 Ω；
- 隔离出来的点对点段必须按实测配置终端。

**监听（并联）与串联（网关）是两种拓扑，不能沿用“关掉采集器 120 Ω”的规则。**

## 7. 建议路线

| 阶段 | 接入点 | 目标 |
|---|---|---|
| 近期原型 | `CH020-2-5/6` EPS 支线 MITM | 只做横向闭环，不依赖 ADDC 身份 |
| 最终 | `EL215-3-14/13` ADDC 支线 MITM | 横向 + 纵向统一替换（需先过三项静态确认） |
| 只读 | `EL231-7/17` | 保留为监听口，不作隔离控制点 |
| 灯光 | `EL215-3-19/20` B-CAN | 先被动抓包，确认 0x23C/0x1F3 的真实入口 |
