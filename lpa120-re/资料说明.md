# 资料说明与文件目录

本文是仓库的“说明书”：数据从哪来、每份文档讲什么、工具怎么用、哪些东西没放进来。

## 1. 项目概述

对象：零跑 B05 / Lafa5 515Pro（内部代号 LPA120），OS 3.01.20。

目标：搞清楚这辆车的 CAN 总线能读到什么、能控制什么，以及 openpilot 接入的可行性与边界。

时间跨度：2026-10-28 至 2026-11-05。

## 2. 数据来源

## 4. DBC（dbc/）

**本仓库不包含任何 `.dbc` 文件。** 矩阵来自厂家加密包，版权归原权利人，`NOTICE.md` 已说明。

`dbc/README.md` 保留了本车用到的 11 份矩阵清单（C_CANFD / COM_CAN / B_CANFD / P_CANFD / ETH_CAN…）
与各自对应的总线，方便你自行准备。

仓库内可用的替代资料：

- `analysis/DBC权威信号表.md`：本项目实际用到的信号（位/因子/偏移/接收方）；
- `analysis/信号解码表.md`、`analysis/0x083_完整解码表.md`：按报文的解码表；
- `analysis/DBC_vs_实测_全量对比.md`：DBC 与实车的差异结论。

## 5. E2E 成果（e2e/）

```
byte0 = CRC8_H2F( data[1..len-1] || seed[counter] )
counter = data[1] & 0x0F
poly 0x2F / init 0xFF / xorout 0xFF / 不反射
```

- `e2e_seed_tables.json`：**56 张**表（QNX 二进制提取）；
- `e2e_seed_tables_observed.json`：**37 张**观测反推表（含 `0x084`），其中 17 张与二进制表逐字节相同；
- 复验：18 条报文约 **130 万帧，0 失配**；
- 工具：`tools/e2e_check.js` 可对任意新帧自动反推 16 项 seed。

## 8. 没有放进仓库的东西

| 内容 | 体积 | 原因 | 如何重建 |
|---|---:|---|---|
| 31 个抓包 ndjson | 1.17 GB | 太大；且含行驶轨迹 | 自采；清单见 `data/captures_manifest_2026-11-04.json` |
| 派生 CSV/JSONL（31 会话） | 576 MB | 可由工具生成 | `carstate_offline.js <ndjson> <prefix>` |
| OTA/整车镜像 | ~20 GB | OEM 版权 + 体积 | 自备 OTA 包 |
| QNX 二进制 | — | OEM 版权 | 自备车机 |
| 固件反汇编源码 | — | 同上 | 见 `analysis/0x083_完整解码表.md` 的方法 |
| DBC 矩阵（11 份） | 5.7 MB | 厂家版权 | 自备 OTA 包并解密 |

## 9. 复现步骤

```bash
# 0) Node.js >= 18，无 npm 依赖
# 1) 用样例验证工具链
node tools/e2e_check.js fixtures/59c08f67.ndjson
node tools/carstate_offline.js fixtures/59c08f67.ndjson /tmp/cs
node tools/verify_carstate.js /tmp/cs.carstate.jsonl
node tools/carstate_offline_test.js

# 2) 用自己的抓包
node tools/dq_gate.js cap.ndjson            # 先过数据质量闸门
node tools/decode_capture2.js cap.ndjson sig.csv
node tools/carstate_offline.js sig.csv out
```

## 10. 已知边界

- **0x2D1/0x2D5**（车道线/目标）布局已知，但不在已抓的 CCAN 上，需 FSC→ICU 链路；
- **0x083 发送**：E2E 已解，但仍需与 ADDC 仲裁，且属安全红线；
- **panda 是经典 CAN**，读不了 32 字节 FD 帧；
- **0x23C 不是 CAN 帧**（只在以太网 DBC 里）；
- 行为类阈值（接管扭矩、设定速度语义）仍需实车样本。
